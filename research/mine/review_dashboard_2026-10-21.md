# Code review: account-cycle simulation, Spanish dashboard, settings cleanup (NQMaster.cs, 2026-10-21)

Scope: commit 41ed9d5 vs 9a8c899 (`git diff 9a8c899 -- NQMaster.cs`). Line numbers are those of the current NQMaster.cs (2,785 lines).
Checks run: `bash tools/nt8_stub/check.sh NQMaster.cs` passes; `python3 tools/propcycle_test/run_test.py` gives 780 cases, 0 mismatches (C# vs research, Python port vs research).
I did not re-audit the PropCycle payout math. NQMaster.cs was not edited.

## Verdict

- **PropMode Off (parity backtests): no change in behaviour.** With `cy == null`:
  - `CyOffset()` is 0.
  - `CycleSessionStart` and `CycleBar` return at once, and `cyHalt` stays false.
  - `AccountGuard`'s `!cyOn` is true.
  - `ApplyPreset()` returns at its first line, as before.
  - The only difference is on a Sim account in realtime: `AcctCash` changed from "Sim101 cash + offset" to "StartBalance + netPnl". With one strategy on the account the two are equal.
- **`ForceRetired()` changes nothing for Ultra, UltraQ, WR70Plus or Durable.** Every forced value equals its SetDefaults value except `UseMom1130` and `UseRsi2`, which are true in SetDefaults. Both are Custom-only (`custom && UseMom1130`, `custom && UseRsi2`), so only the Custom profile changes: with default settings it no longer runs MOM1130 or RSI2.
- **The state machine is sound while the cycle is running.** I found no double counting of days or fees, and no day closed twice:
  - DayClose runs once per session, only for an account that is alive.
  - Bust and pass days are never closed, which matches the research.
  - Waiting for the MFFU minimum days reproduces the research's `max(d, mind-1)`. Example: pass on the 2nd day -> funded account from session index 4.
  - After the last payout, a new eval starts in the next session.
  - The phase snapshot covers every field `ApplyPreset` writes. HedgeGroup is the only exception, and setting it is idempotent.
  - Nothing computed once at DataLoaded depends on the preset values. BuildModules and EdgeParams read only Profile and the module switches.
- **The real bugs are at the go-live boundary and in realtime on a Sim account:**
  - 1 HIGH: a real prop account can be blocked forever.
  - 4 MEDIUM.
  - The rest are LOW.

## Things checked and found correct

- **Session-start order:**
  1. `ProcessClosedTrades` books the previous session's exits first, so DayClose sees them.
  2. Then `StatDayClose`, `CycleSessionStart` (DayClose, then CyStart), `PropSessionStart` and `edgeDayQty`.
  3. `PropSessionStart` overrides peak and threshold from `cy.Pk` / `cy.Thr` while the account is alive, so the risk cap, the step-up and the ladder use the simulated cushion.
- **Bust and pass flatten:**
  - FlattenAll's one-per-bar guard only skips a duplicate exit.
  - `CanTrade` false cancels entries and parked orders on later bars.
  - The 5-minute ICT path goes through `CanTrade`.
  - The bust's flatten loss lands in `netPnl` before the next account's `cyBase`.
- **Profit/loss stops:** `PropDailyCheck` uses `propDayStart` set after the payout withdrawal, so a payout is not counted as a losing day. The eval profit stops (Lucid 1,350 / MFFU 800 / Lucid150K 4,050) and the funded FundedProfitStop apply per phase.
- **`targetHit`** is reset at CyStart and at go-live. `AccountGuard`'s target check is skipped while the cycle runs (`!cyOn`) and works again on a real account after the freeze.
- **Go-live ordering:**
  1. `hq` is taken before `CycleGoLive`, and `lq` after `PropGoLive`, so working orders are resized correctly (see #2 for parked orders).
  2. `PropGoLive` reads the prop file after the real phase and preset are restored. On Sim, `PropGoLive` returns without touching the prop file.
- **Payout level per firm model:** Model 0 X = FundedPayoutAt; Model 1 X = FundedPayoutAt − (D+100), which gives LucidPro50K 2,000 and LucidPro25K 1,000; Model 2 X = FundedPayoutAt − 500, which gives MFFU 4,100 and ladder 11,100. These match the research and propcycle.py.
- **Dashboard divisions are all guarded:** PF, WR, per trade, green days, edge %, live expectation, evals pass %, consistency line. #10 and #11 are cosmetic only.
