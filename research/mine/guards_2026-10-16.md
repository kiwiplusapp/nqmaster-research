# Import guards: audit of 2026-10-16

Why: many research scripts do their work at module level. When another script imports one of them, that work runs again without
anyone noticing and can overwrite shared files. This already happened on 2026-10-06: importing `dense_build.py` / `ict_redo.py`
wiped keys in `research/tmp/dense/*.npz`.

## New tool: `tools/check_guards.py`

A static scanner. It uses `ast` only and never executes the scripts.

```bash
python3 tools/check_guards.py          # table of imported modules that have top-level work; exit 1 if any is unaccepted
python3 tools/check_guards.py --all    # also lists scripts nobody imports (informational)
```

**What counts as imported.** A file counts as imported when another file runs `import X` or `from X import ...`, where `X` is a
module in the importer's own directory or in `research/`. The same directory wins, as at run time.

**What counts as unsafe.** Any top-level statement except:
- imports, `def` / `class`, docstrings;
- `if __name__ == "__main__":` blocks, including `... and X`;
- `sys.path` changes;
- constant and config assignments.

**Call purity.** A call is pure when it is a builtin, `os.path`, a numpy constructor, a str/dict/list method, or a function
whose body contains only such calls. That function can be in the module itself or in another research module (checked to a
fixpoint). Loops and if/try blocks made only of pure statements count as constant building.

**Writes.** Statements that write files are marked `W` and the file gets status `WRITES`. A statement writes when it calls
`to_csv`, a pickle/json dump, `np.save*`, `open(..., "w")`, and so on. This is followed through every function it calls, across
modules and class methods.

**Accepting a statement.** Mark it with `# guard-ok: <reason>` on its line or the line above it, or put it between
`# guard-ok-begin: <reason>` and `# guard-ok-end`. Accepted statements are listed but do not fail the check. **Use this only for
read-only work that importers rely on.**

**exec-prefix dependencies.** The pattern `exec(open("X.py").read().split(MARK)[0])` is listed in a separate table: 27 such
dependencies today. For each one the scanner checks two things:
- MARK still occurs in X and the prefix still parses. A broken split fails the check.
- Whether the prefix writes files. This is reported but does not fail the check.

### Missing dense keys now raise `KeyError` (5 files)

What the code did before:
- `acct_lab.sums()` **silently skipped** a missing key (`if m + "|L" in z.files`). It printed no WARNING, despite what the
  10-06 memory says.
- `acct1c_lib._key()` printed a WARNING and fell back to `"U:" + name` for **any** missing key. For example, a missing
  `WR:X` or `G:X` would have read the Ultra module `U:X`, which is the wrong module.
- `eval_opt.grids()`, `final_verify.exits()` and `final_verify_lib.exits()` skipped missing keys with `continue` or `if`.

New in `acct_lab`: `dense_key(per, k)` and `DENSE_ALIAS`.
- A missing key raises `KeyError` naming the key, the period and the `.npz` file, plus the rebuild order
  (dense_build -> ict_redo -> dense_profiles -> dense_extra -> gnq_port -> nqdrive_port).
- There is one exact alias: `U1:MSEQS` -> `U:MSEQS`.
  - `dense_build.py` writes `U1:X` only when the period has a boosted X trade.
  - REAL has none for MSEQS, so `U1:MSEQS` would be identical to `U:MSEQS`. I verified this: `sums("REAL", ["U1:MSEQS"])`
    equals the `U:MSEQS` grid.
- `sums`, `acct1c_lib._key`, `eval_opt.grids` (mine/), `final_verify.exits` and `final_verify_lib.exits` all use `dense_key`
  now.
- Every config list in `acct_policy.CFG`, `acct_life.CFG` and `acct1c_lib` resolves in all three periods (83 lists checked), so
  current scripts do not start failing.

**Effect on earlier results.** Through `acct_lab.sums`, the configs `NOB`, `UA_NOB`, `UA_NOB_GW` and `UA_NOB_GR` (`acct_policy` /
`acct_life` / `prof_grid*`) have been **missing MSEQS in REAL** until now.
- MSEQS in REAL: +$1,784 over 657 days, i.e. about **+$57 per month**.
- That is about 2.7% of the NOB REAL monthly P&L ($2,090 -> $2,147).
- It affects only REAL numbers of policies that used the no-boost tier (the cushion-gating / EQ2 funded tiers of 2026-10-05/06).
  It is small, and the sign is in favour of NOB.
- `acct1c_lib` (2026-10-07 and later) already used the correct fallback, so it is unaffected.

## Not done and why

- **Lazy loading of the heavy read-only modules** (`fast1c`, `gnq_check`, `crt`, `wr60`, ...).
  - Importers use the module-level data names directly, so making them lazy would mean editing the importers too.
  - Importing these modules is slow but writes nothing.
  - The safe way to do it later is a module-level `__getattr__` plus changing the module's own functions to read through a
    getter.
- **exec-prefix dependencies** were not changed.
  - `pullday_eval3.py` runs the prefix of `pullday_eval2.py`, which writes `pullday_portfolio_trades.pkl`. That is the
    intended work of that script.
  - Changing those targets would change the text the importers execute.
- **217 scripts that nobody imports** still do top-level work, and 166 of them write files. That is normal for scripts and is
  harmless as long as nobody imports them. The checker will flag one as soon as something imports it.
- `NQMaster.cs`, `GoldMaster.cs` and `research/data` were not touched. Nothing was committed.

## Rule for new research code

Put work under `if __name__ == "__main__":`. Run `python3 tools/check_guards.py` before committing. Exit code 1 means a script
now imports a module that does unguarded work.
